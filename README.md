# 物联网仿真实训教学平台 · 本地部署包

把一套物联网仿真实训教学平台部署到本机运行，**不依赖校园网**。
包含前端应用、自建后端、教学素材三部分，开箱即用。

---

## 快速开始

### 方式一：发布包（推荐，无需装任何环境）

到 [Releases](https://github.com/Aaron-gx/nle-emulator-local/releases) 下载
`物联网仿真平台-vX.Y.Z-win64.zip`，解压后**双击 `物联网仿真平台.exe`**：

- 首次运行自动建库并导入数据
- 服务就绪后自动打开浏览器
- 默认账号 `local-admin / local-admin`（无需配置）

### 方式二：源码运行

需要 **Node.js 22 或更高**（用到内置 `node:sqlite`，无需额外安装数据库）。

```powershell
# 1. 配置账号
Copy-Item .env.example .env
#    编辑 .env，填写 NLE_USER / NLE_PASS（本地登录用）

# 2. 启动（首次会自动建库并导入数据）
.\start.ps1

# 3. 浏览器打开
#    教学平台  http://127.0.0.1:8090/training/
#    仿真平台  http://127.0.0.1:8090/emulator/
#    通行证    http://127.0.0.1:8090/account/
```

`start.ps1` 会同时启动：

- **后端** `127.0.0.1:8091` —— 业务接口与数据（SQLite）
- **前端** `127.0.0.1:8090` —— 三个应用的静态服务，并把接口请求转发到后端

端口被占用时会自动顺延；换端口用 `.\start.ps1 -Port 9000`。

## 需要另外准备的两样

本地部署包不含它们，请按需自备：

### 1. 桌面助手（仿真功能的前提）

仿真平台画布中的设备拖拽、连线与仿真运行，由本机的一个独立进程负责，
浏览器通过 `ws://127.0.0.1:6600` 与它通信。

未安装时仿真平台会提示"未安装或未打开桌面仿真助手"，**此时仿真实验无法运行**，但其余功能正常。

安装包：`NLEEmulatorClientAssistant.exe`（厂商提供，约 32 MB）。
双击安装并启动后，仿真功能即可使用。

### 2. 文档渲染服务（可选）

在线预览 Office / PDF 课件需要 [kkFileView](https://github.com/kekingcn/kkFileView)。
本包只含其前端页面，不含渲染后端。若需预览课件：

```powershell
docker run -d -p 8012:8012 keking/kkfileview
```

不需要预览文档时可以忽略。

## 目录结构

```
site/                前端应用（教学平台 / 仿真平台 / 通行证 / 文档预览）
site_readable/       反格式化后的前端源码，便于二次开发
backend/             后端服务
  ├─ server.mjs      API 服务
  ├─ db.mjs          数据库结构
  ├─ import.mjs      数据导入
  ├─ n2v.mjs         .N2V 工程包解密/加密
  ├─ verify.mjs      接口自检（30 项）
  └─ offline-test.mjs 离线自检（17 项）
server/serve.mjs     静态服务与接口转发
launcher/            一键启动器（Node SEA 打包为独立 exe，见 launcher/README.md）
data/                业务数据与教学素材
start.ps1            一键启动（源码方式）
```

### 架构

前后端分离，两个 Node 进程，HTTP 通信：

```
浏览器
  │
  ▼
8090  server/serve.mjs     静态文件 + 反向代理 + 登录态桥接
  │
  ▼  /training-server/* /emulator-server/* /gateway/*
8091  backend/server.mjs   纯 API 服务 + SQLite
```

仿真功能的设备通信不经过这两层：浏览器直连本地桌面助手
`ws://127.0.0.1:6600`（厂商组件）。

## 配置说明

`.env` 由 `.env.example` 复制而来，各项含义：

| 变量 | 说明 |
|---|---|
| `NLE_USER` / `NLE_PASS` | 本地登录账号与密码 |
| `S_PORT` / `B_PORT` | 前端 / 后端端口 |
| `NLE_LOCAL` / `NLE_BACKEND` | 前端访问地址 / 后端地址 |

`.env` 已被 gitignore，不会进入版本库。

## 教学素材

`data/assets/` 内含随包提供的教学素材：

```
课件      章节教学文档（.docx）
视频      实操演示视频（.mp4）
源码      编码练习示例（.cs）
案例      项目案例包（.zip）

```

**仿真工程文件（`.N2V`）可直接导入**：在仿真平台工具栏选择文件即可，
后端使用前端内置的密钥做真实解密（见 `backend/n2v.mjs`），导入哪个文件
就载入哪个工程。`data/assets/` 已附带数个示例工程（克隆仓库时被
gitignore，可从发布包获取）。早期的 `backend/data/n2v/` 明文库机制已废弃。

## 自检

```powershell
cd backend
node verify.mjs           # 接口契约自检，应全部通过
node offline-test.mjs     # 断网自检：上游不可达时整站仍可运行
```

`offline-test.mjs` 会临时使用 8095/8096 端口，结束后自动释放。

## 已知限制

- 文档预览需要额外的 kkFileView 后端（见上）
- 仿真运行需要桌面助手（见上）
- 代码编译类实训依赖厂商在线编译服务，离线环境不可用
- 课程目录结构未包含（素材以文件形式提供）
- 云平台（ndp.nlecloud.com）**下行控制不可用**：仿真固件内的设备密钥是
  厂商默认值，与你在云端注册设备的 SecretKey 不一致时，云端不会下发
  `$#CTLO` 控制指令（上传与"在线"状态不受影响）。对齐密钥后即可恢复
- 内置学生账号未配置手机号，默认只有 `.env`（或首次建库的
  `local-admin`）管理员可以登录
